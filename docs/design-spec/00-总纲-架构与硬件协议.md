# 00 · 总纲：多程序固件架构与硬件协议规范

> **文件用途**：本总纲 + 三份分册（01 桌宠屏保 / 02 单摆测g / 03 天气）构成完整的编程规范包。
> 交给 AI 编程时的用法：**投喂本总纲 + 对应分册**，并附指令「你负责实现《XX分册》定义的模块，严格遵守总纲全部约束，禁止越界改动其他模块」。上一轮对话已完成纯逻辑设计并冻结，编程阶段**不得推翻已裁决的设计**。

## 1. 项目一句话与全局约束

为立创 ESP32-S3 开发板构建「任务管理器式」多程序固件：常驻 3 个程序（1 桌宠屏保【默认 · 开机运行 · 空闲屏保】、2 单摆测g、3 实时天气），长按按键切换，非活跃程序完全挂起省资源，所有状态与联网数据**断电可恢复、断网降级不崩**。

**硬约束（来自前期已冻结设计，不得更改）：**
- 上电**无条件默认激活程序 1**（管理器不记忆"上次程序"）；程序 1 = 桌宠屏保
- **屏保策略**：程序 1（桌宠）同时承担「屏保 / home」角色——当活跃程序为 2 或 3 且连续无交互超过 `sys.screen_saver_timeout`（默认 180s，0=关闭）时，管理器自动切回程序 1；程序 1 自身在 home 时不触发自动回家；程序 1 在 idle 5 分钟后走 L3 熄屏
- 长按 ≥0.8s = 切换程序（管理器拦截）；短按 = 转发当前活跃程序；超长按 ≥5s = 系统重启（预留）
  - 2026-10-02 修订：阈值 1.2s → **0.8s**。原值在「按键采样 10Hz + 天气程序 15-25s 阻塞」下实测完全无法触发
- **两级节拍铁律（2026-10-02 新增）**：按键采样 `LOOP_INTERVAL_MS` 10ms（100Hz），`onTick` 业务分发 `TICK_INTERVAL_MS` 100ms（≤10Hz）。二者必须解耦——按键可靠性不能受业务节拍拖累，但业务重活也不能被 100Hz 拖起来
- **主循环禁止阻塞（2026-10-02 新增）**：`onTick` 内不得出现 HTTP / DNS / `delay`>50ms 等阻塞调用。按键状态机的唯一采样点在主循环，一阻塞按键即失灵。阻塞网络操作必须放独立 FreeRTOS 任务
- 非活跃程序 CPU 占用必须为 0（挂起状态机，不是空转）
- 所有联网数据必须「时间戳 + 缓存」双写，断网显示缓存并标注数据年龄
- 原单摆"长按复位"已废除，由「开始测量自动清零 + BLE 菜单清空」替代

## 2. 硬件基线（实际采购件）

| 项 | 规格 |
|---|---|
| 主控 | 立创 LCKFB-ESP32S3R8N8（ESP32-S3，8MB Flash + 8MB PSRAM，DIP-40 已焊排针，跨插 830 面包板） |
| 显示 | 1.3″ OLED，驱动芯片 **SH1106**（1.3″ 屏专用；与 SSD1306 指令集<b>不完全兼容</b>，<b>不可</b>直接沿用 SSD1306 库），I²C 4 针，丝印序 GND-VCC-SCL-SDA，已焊排针 |
| 按键 | 轻触按键 6×6，接 GPIO5，另一端接 GND |
| 光电门 | 15mm 宽槽对射红外模块（LM393 比较器），**5V 专用供电**（底轨），OUT 空闲 5V |
| 电平转换 | 8 路 BSS138 双向模块，仅用 A0/B0 一路：光电门 OUT→B0，A0→GPIO4 |
| 电源 | 双电源轨：顶轨 3.3V（ESP32 3V3 输出，供 OLED + 电平转换 VCCA）；底轨 5V（MB102 电源模块，供光电门 VCC + VCCB）；两轨共地 |

## 3. 引脚与电气协议（实际硬件）

| 引脚 | 功能 | 电气说明 |
|---|---|---|
| GPIO4 | 光电门信号输入 | 经 BSS138 电平转换后为 3.3V 域信号：**空闲高（≈3.3V）、遮挡低（≈0V）**；配置 INPUT_PULLUP（转换模块侧已有上拉，内部上拉仅作保险）；**中断 FALLING = 遮挡开始**；极性相反时改 RISING |
| GPIO5 | 按键输入 | INPUT_PULLUP，按下=LOW；软件消抖 |
| GPIO8 | I²C SDA | Wire 默认引脚 |
| GPIO9 | I²C SCL | Wire 默认引脚 |
| 3V3 / GND | 顶轨电源 | 供 OLED 与电平转换 VCCA |

**I²C / OLED 协议**：地址 **0x3C**（7 位，失败试 0x3D）；SH1106 与 SSD1306 指令集<b>不完全兼容</b>，驱动库<b>必须</b>用 SH1106 专用库（Adafruit_SH1106 或 U8g2/U8G2_SH1106_128X64_NONAME_F_HW_I2C）；ESP32-S3 需在初始化前 <code>Wire.begin(8, 9)</code> 指定 I²C 引脚（默认 21/22 不匹配本项目）；128×64 单色；初始化失败则停机报错（程序 1 待机页显示错误）。

**BLE 协议**：ESP32-S3 **仅支持 BLE，无经典蓝牙 SPP**。串口透传统一使用 **Nordic UART Service (NUS)**：
- Service UUID：`6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- RX 特征（PC→板，板端写）：`6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
- TX 特征（板→PC，Notify）：`6E400003-B5A3-F393-E0A9-E50E24DCCA9E`
- 文本按行传输，行尾 `\n`；单包不超过 MTU-3 字节；板端广播名 `pendulum-g`
- BLE 常备可连接（不被任何省电级别关闭）

**WiFi / 时间协议**：仅 2.4GHz，WPA2-PSK；凭据存 NVS；SNTP 服务器 `ntp.aliyun.com`（备选 `pool.ntp.org`），时区 GMT+8；WiFi 空闲 5 分钟自动断开并进调制解调器休眠，断网各程序走缓存降级。

**天气 HTTP 协议**（详见分册 02）：和风天气 QWeather v7。⚠️ 2026-10-02 修正：原定「响应为 GZIP 压缩」在本工具链**不可行**——esp32:esp32 3.3.12-cn 不含 zlib（全盘无 `zlib.h`/`libz.a`），故改 `Accept-Encoding: identity` 取明文（实测 now ≈311 B、24h ≈859 B，压缩收益可忽略）。响应处理按魔数 `0x1F 0x8B` 嗅探兜底。

## 5. 程序管理器规范（主）

### 5.1 注册表
| 槽位 | 程序 | 短按主功能 | 常态资源 |
|---|---|---|---|
| 1（默认 · 屏保） | 桌宠屏保 | 互动换表情（home / 空闲屏保） | OLED（1–2fps）、事件订阅 |
| 2 | 单摆测 g | 开始/停止测量 | GPIO4 中断（活跃时才挂载）、OLED、BLE 菜单 |
| 3 | 实时天气 | 四屏切换 | OLED、WiFi（30 分钟一次，用完释放） |

### 5.2 生命周期钩子契约（每个程序实现同一组）
| 钩子 | 时机 | 必须做 | 禁止 |
|---|---|---|---|
| onCreate | 首次激活前 | 从 NVS 恢复状态、申请常驻资源 | 阻塞联网 |
| onShow | 成为活跃 | 申请屏幕授权、挂载中断/定时器、重绘首屏 | 长循环 |
| onHide | 失去活跃 | **状态写 NVS、注销中断/定时器、归还屏幕**（同步完成，不许延迟） | 留资源尾巴 |
| onButton | 短按转发 | 程序内主功能 | — |
| onTick(dt) | 活跃期间 ≤10Hz | 刷显示、推进状态机 | 单次 >50ms |
| onBleMsg(text) | 收到本程序注册的 BLE 命令 | 执行并回文本行 | — |
| onEvent(evt) | 订阅的全局事件到达 | 更新内部状态 | — |

### 5.3 全局事件总线（管理器广播，程序订阅）
`EVT_NET_GOT` / `EVT_NET_LOST` / `EVT_BLE_CONN` / `EVT_BLE_DISC` / `EVT_MEASURE_DONE`（负载：本次 g）/ `EVT_WX_UPDATE_OK` / `EVT_WX_UPDATE_FAIL`（负载：错误码）。

### 5.4 省电分级
L0 屏保回家（系统级）：活跃程序为 2/3 且连续无交互 > `sys.screen_saver_timeout`（默认 180s）时，自动切回程序 1（桌宠）；程序 1 自身在 home 不触发；测量进行中（程序 2 测量态）不触发。
L1 应用挂起（非活跃程序零调度）；L2 外设回收（屏幕独占授权、WiFi 懒连接 5 分钟断开、BLE 常备）；L3 五分钟无操作 OLED 熄屏（先由程序 1 显示瞌睡 1 分钟再灭；任意按键唤醒）；L4 深度睡眠（暂缓，不做）。

### 5.5 上电时序
初始化外设与 NVS → 读全局配置 → 注册三程序 → **激活程序 1（桌宠）** → 程序 1 onCreate 恢复 pet_mood 等 → 屏保待机显示。SNTP 对时与 WiFi 重连在后台异步进行，不阻塞首屏。

## 6. 公共服务契约
| 服务 | 契约要点 |
|---|---|
| 显示服务 | 屏幕独占授权制：仅活跃程序持有；挂起即被强制回收；统一缓冲后整帧提交 |
| 存储服务 | 键值 get/set（命名空间强制 `sys./app1./app2./app3.`）；历史记录 append/list/export/clear 统一由存储服务管理 |
| 网络服务 | 程序只发「连接请求」，不碰 WiFi 驱动；连接/断开广播 EVT_NET_*；HTTP GET 封装（本工具链无 zlib，identity 明文 + GZIP 魔数嗅探）|
| BLE 服务 | 常备 NUS 从机；菜单注册表：系统注册全局项，各程序注册自己的项；收到的行文本路由到对应菜单处理器 |
| 时间服务 | SNTP 对时、毫秒时间戳；一切时间戳取自本服务 |

**BLE 全局菜单树（固定，系统注册）：**
```
[1] WiFi 配网
    1.1 用已存凭据连接测试   1.2 扫描SSID列表→选序号→输密码→保存连接
    1.3 查看连接状态
[2] 摆长（程序2注册）    [3] 历史数据（程序2注册）    [4] 天气（程序3注册）
[0] 状态总览（固件版本/当前程序/剩余NVS/当地g来源）
```
回包协议：每行以 `OK:` / `ERR:` / `INFO:` 前缀开头；列表项用 `INFO: [n] xxx`；导出流用 `#EXPORT BEGIN,<count>` … `#EXPORT END` 包裹（明细见分册 01）。

## 8. 编码规范
1. **非阻塞铁律**：任何钩子单次 ≤50ms；联网/写Flash/导出一律异步回调
2. 错误码三族：`E_NET_xxx / E_NVS_xxx / E_SENSOR_xxx`；程序级错误在 OLED 显示一行可读文案（并联动程序 1 表情）
3. OLED 字段沿用原版命名：`g / n / t / L / sG / N / G / err`，新增信息只许角落小字，不得破坏 4 行布局
4. 每程序独立目录 + 模块头注释（职责/钩子实现/NVS 键/BLE 菜单）
5. 禁止硬编码 WiFi 密码、Key 进源码——全部走 NVS
   - **修订（2026-09-30）**：WiFi 支持内置默认回退列表——`fw_config.h` 可填少量默认网络（**开源版已清空为占位**），NVS 用户凭据（BLE 配网）优先，失败自动轮换。
   - **修订（2026-10-02，用户明确要求「将 key 写入固件」）**：天气 Key/Host 同样内置（`WX_KEY_DEFAULT`/`WX_HOST_DEFAULT`），NVS（BLE 4.4）优先，`app3` 另有兜底回落。公开源码前必须清空
6. 中断共享变量：`volatile` + 读写临界区（noInterrupts/interrupts 包裹读取）

## 9. 全局验收清单（M1–M5 见分册）

# 01 · 分册：程序 1「桌宠屏保 / AI 桌宠」（默认开机程序 · 空闲屏保 · home）

> **配套**：必须与《00-总纲-架构与硬件协议》一起投喂。总纲引脚、BLE、NVS、生命周期、事件总线规范全部适用。

## 1. 职责与边界
- **角色（最高优先级）**：程序 1 = **开机默认激活程序 + 空闲屏保 + home**。上电无条件进入本程序（管理器不记忆"上次程序"）；当活跃程序为 2/3 且连续无交互超过 `sys.screen_saver_timeout`（默认 180s，0=关闭）时，管理器自动切回本程序；本程序在 home 态自身不触发自动回家；idle 5 分钟后走 L3 熄屏。
- 必做：颜文字表情状态机 + 按键互动 + 全局事件联动（测量完成/天气更新/联网状态）+ 瞌睡熄屏协作
- 可选（非强制，接口留桩）：RSS 新闻模块；AI 问答模块（仅预留 onBleMsg 文字问答桩，不实现模型对接）
- 边界：表情是全局情绪出口但**屏幕授权仍按活跃程序规则**——程序 1 表情的"联动浮现"以通知条形式叠加在当前活跃程序（程序 2 或 3）画面角落 3–5 秒（由显示服务提供通知条能力），不抢屏；仅当程序 1 本身活跃（home / 屏保态）时才全屏演表情

## 2. 硬件协议速查（本程序相关）
| 项 | 值 |
|---|---|
| OLED | I²C 0x3C，128×64，SH1106 专用库（Adafruit_SH1106 或 U8g2）；SDA=GPIO8 SCL=GPIO9；ESP32-S3 需 Wire.begin(8,9) |
| 按键 | GPIO5；短按=互动（管理器转发）；长按已被管理器占用为切程序 |
| 事件 | 订阅 `EVT_MEASURE_DONE / EVT_WX_UPDATE_OK / EVT_WX_UPDATE_FAIL / EVT_NET_LOST / EVT_NET_GOT / EVT_BLE_CONN / EVT_BLE_DISC` |
| 帧率 | 表情动画 **1–2 fps**（低功耗），通知条 3–5s 自动消失 |

## 3. 表情状态机（必做）

### 3.1 状态与颜文字帧（每态 ≥2 帧，帧间 500–1000ms 交替）
| 状态 | 帧示例（可微调字形，保持颜文字风格） | 进入条件 |
|---|---|---|
| 待机 idle | `^(o_o)^` ⇄ `^(－_－)^`（慢眨眼） | 默认态 |
| 打招呼 hi | `(^o^)/` ⇄ `(^o^)丿` | 上电首次 onShow；切入程序 1 |
| 开心 happy | `(*^▽^*)` ⇄ `＼(^▽^)／` | 待机中短按 |
| 彩蛋 spin | `(≧▽≦) ~(~랗~)~` 连转 | 待机中 3s 内连按 3 次 |
| 瞌睡 sleepy | `(－_－) zzZ` 静帧 | 5 分钟无操作 |
| 庆祝 cheer | `＼(^o^)／` ⇄ `ヽ(°▽°)ノ` | EVT_MEASURE_DONE（通知条含本次 g） |
| 天气喜 wxok | `(＾▽＾)` | EVT_WX_UPDATE_OK |
| 难过 sad | `(T_T)` ⇄ `(；´д｀)` | EVT_WX_UPDATE_FAIL / EVT_NET_LOST / 传感器错误码 |

### 3.2 转移规则
| 当前态 | 事件 | 次态（停留时长后自动回 idle） |
|---|---|---|
| idle | 短按 | happy（3s） |
| idle | 3s 内第 3 次短按 | spin（2s） |
| idle | 上电/切入 | hi（3s） |
| idle | EVT_MEASURE_DONE | cheer（5s，通知条显示 g 值） |
| idle | EVT_WX_UPDATE_OK / FAIL / NET_LOST | wxok（3s）/ sad（持续至恢复） |
| idle | 5min 无操作 | sleepy → 1min 后请求显示服务熄屏（L3） |
| sleepy | 任意按键 | idle（并取消熄屏请求） |
| 任意短暂态 | 计时到 | idle |

- `EVT_NET_GOT / EVT_BLE_CONN` 恢复：若因 sad 长驻则回 idle
- 状态变化写 `app1.pet_mood`，onCreate 恢复（断电重启从上次的 idle/sad 等合理态开始）

## 4. 熄屏协作
- 瞌睡 1 分钟后向显示服务发「熄屏请求」→ 显示服务灭 OLED（SH1106 关显示指令）
- 任意按键由管理器先唤醒本程序（不转发短按主功能这一次），再走正常路由

## 5. 可选模块 A：RSS 新闻（非强制，M5 后可做）
- 拉取：每小时一次（仅在线时）；源做成配置项（默认建议新华网/人民网 RSS，URL 可 BLE 修改）
- 解析：取最新 5 条 `<title>`，每条截前 10 字
- 显示：程序 1 活跃且 idle 态时，底部滚动条轮播；写 `app1.news_cache`，断电/断网可看旧闻（标注「HH:MM 新闻」）
- 失败静默：不广播难过表情（新闻属装饰功能）

## 6. 可选模块 B：AI 问答（非强制，仅留桩）
- 背景：小智 AI（github.com/78/xiaozhi-esp32）为独立整机固件且需 INMP441 麦克风 + MAX98357 功放，与本任务管理器互斥，本轮**不烧录、不对接**
- 本固件预留桩：`app1.onBleMsg` 增加菜单 `[5] AI问答（未启用）`，回复 `INFO: AI 模块未启用`；后期若启用，走 WebSocket→LLM 服务端自研路线（参考小智协议），OLED 滚动回复，走缓存降级
- **禁止**：任何实现里引入小智固件代码或其云服务依赖

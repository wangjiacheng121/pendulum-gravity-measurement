# 03 · 分册：程序 3「实时天气」

> **配套**：必须与《00-总纲-架构与硬件协议》一起投喂。总纲引脚、BLE、NVS、生命周期规范全部适用。

## 1. 职责与边界

- 职责：定时拉取和风天气数据 → 四屏显示（短按切换）→ 缓存降级；BLE 注册天气菜单
- 边界：不管理 WiFi 连接（走网络服务，含 HTTP GET 封装）；不碰程序 1/3 的 NVS 键；拉取失败**绝不切屏、绝不打断当前显示**，只更新状态角标

## 2. 数据源协议（已选定，接口预对接——用户只填 Key 和 Host）

**平台**：和风天气 QWeather v7，免费订阅（1000 次/天，实际日耗 ≈48 次）。  
**申请网址**： → 注册 → 控制台「项目管理」→ 创建项目 → 选择「**免费订阅**」→ 设置 KEY（类型 Web API）→ 复制 **KEY** 与控制台分配的 **API Host**（免费版为账号专属域名，形如 `xxx.qweatherapi.com`，以控制台「设置」页为准）。  
用户填入 `sys.wx_key` 与 `sys.wx_host`（BLE 菜单 `4.4`；**出厂由 `fw_config.h` 内置**）

**获取你自己的凭据（和风天气免费订阅 v7）**：
- 凭据ID：在和风天气控制台「设置→凭据管理」获取（格式如 `XXXXXXXXXXXX`）
- API Key：同上获取（格式如 `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
- API Host（由凭据ID小写 + 区域构成）：`https://<你的凭据ID小写>.free.qweatherapi.com` ⚠️ **请到控制台「设置→凭据管理」核对该凭据的实际 Host**；免费版区域一般为 `free`，若控制台显示 `cn`/`re`/`ap`/`eu`/`us` 请改其后缀，以控制台显示为准。

> **修订（2026-10-02，用户明确要求「将 key 写入固件」）**：原先 Key/Host 只走 NVS、出厂留空，
> 必须先经 BLE 4.4 配一次才能拉天气。现改为内置于 `fw_config.h` 的
> `WX_HOST_DEFAULT` / `WX_KEY_DEFAULT`，**通电即用**。
> 优先级：NVS（BLE 4.4 写入）> 内置值 —— 换账号不必重刷固件；
> `app3_weather.cpp` 另有兜底，NVS 被清空时回落到内置值。
> ⚠️ 与 `WIFI_DEF_*` 同属个人私有凭据，**公开源码前必须清空**。

程序运行时通过 BLE 菜单 4.4 或配网脚本将上述值写入 `sys.wx_key` / `sys.wx_host`；源码对应常量保持空串占位，禁止把 Key 编译进固件。。

### 2.1 请求规范（实际协议，必须照此实现）

| 项                 | 值                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------ |
| 实时天气              | `GET https://{wx_host}/v7/weather/now?location={lon},{lat}&key={KEY}&lang=zh&unit=m` |
| 逐小时预报（取未来 6 小时降水） | `GET https://{wx_host}/v7/weather/24h?location={lon},{lat}&key={KEY}&lang=zh&unit=m` |
| 城市兜底查询（GeoAPI）    | `GET https://{wx_host}/geo/v2/city/lookup?location={关键词}&key={KEY}&number=1`         |
| **坐标参数格式**        | **经度在前、纬度在后**，逗号分隔（如 `114.88,40.77`）——QWeather 专有格式，勿写反                              |
| **响应编码**          | **identity 明文**（本 core 无 zlib，见总纲修正）；代码含 GZIP 魔数 `0x1F 0x8B` 嗅探兜底     |
| 请求头               | `Accept-Encoding: identity`（无 zlib 不可用 gzip）；超时 10s；失败重试 1 次，间隔 30s          |

### 2.2 需解析的字段

- `/weather/now`：`obsTime, temp, feelsLike, text, windDir, windScale, windSpeed, humidity`
- `/weather/24h`：逐小时 `fxTime, pop（降水概率%）, precip`——取未来 6 小时；并计算「下一场降水开始时间」= 第一个 pop≥30% 的 fxTime（无则空）

### 2.3 地址精度链（默认张家口市第一中学）

1. **默认**：经纬度直接查询 `sys.loc_lon=114.88, sys.loc_lat=40.77`（坐标为可配置项，交付前用地图工具核对精确值）
2. 降级：GeoAPI 查「张家口」取 LocationID（城市级）
3. 兜底显示：数据缺失时该屏显示 `--`，不报错刷屏

## 3. 更新与缓存策略

- 周期：每 **30 分钟**后台拉取一次（now + 24h 两个请求）；`EVT_NET_LOST` 期间暂停拉取，恢复后立即补一次
- 每次成功：解析 → 写 `app3.wx_now / app3.wx_hourly`（含时间戳）→ 广播 `EVT_WX_UPDATE_OK`；失败广播 `EVT_WX_UPDATE_FAIL(错误码)`
- 显示数据一律来自缓存区（即便在线也先写缓存再显示，保证读写路径唯一）；每屏角落标注「HH:MM 数据」年龄；年龄 >24h 追加 `!` 警示符

## 4. 四屏显示定义（短按循环切换，顺序固定）

| 屏      | 主显（大字）                                | 辅显（小字）                             |
| ------ | ------------------------------------- | ---------------------------------- |
| ① 气温   | `<temp>°C`                            | `体感 <feelsLike>°C  湿度 <humidity>%` |
| ② 天气   | `<text>`（中文现象）+ 简笔点阵图标（晴/云/雨/雪/雾 5 类） | `今日 <最高temp>/<最低temp>`（从 24h 首日取）  |
| ③ 风速   | `<windSpeed> km/h`                    | `<windDir> <windScale>级`           |
| ④ 未来降水 | 未来 6 小时 pop 竖条点阵图（0–100% 映射条高）        | `降水约从 <fxTime> 开始`（无则 `未来6h无明显降水`） |

- 短按 = 下一屏并写 `app3.wx_page`；onShow 恢复上次屏
- 首次无任何缓存：显示「等待天气数据…（配网后自动获取）」+ 桌宠难过表情联动（广播的 FAIL 事件由程序 1 消费）

## 5. BLE 菜单（程序 3 注册）

```
[4] 天气
    4.1 查看状态 → INFO: Key=<已配置> Host=<已配置>（值见第2节「已配凭据」）
                 INFO: 坐标=<lon>,<lat> 上次更新=<HH:MM> 错误=<最近错误码/无>
    4.2 修改坐标 → 提示输入「经度,纬度」→ 校验范围（经度73–135，纬度3–54）→ 写 sys.loc_* → OK → 立即触发一次拉取
    4.3 立即更新 → 触发一次后台拉取 → OK: 已提交
    4.4 配置 Key/Host → 分两步提示输入 → 写 sys.wx_key / sys.wx_host（回显时 Key 打码）
```

## 6. NVS 读写规则

- `wx_host/wx_key/loc_*`：BLE 写入即持久；**出厂由 `fw_config.h` 内置（2026-10-02 起，见第 2 节修订）**，NVS 优先于内置值
- `app3.wx_now / app3.wx_hourly`：每次成功拉取即写（含 ts）；onCreate 恢复用于断电后首屏
- `app3.wx_page`：切屏即写

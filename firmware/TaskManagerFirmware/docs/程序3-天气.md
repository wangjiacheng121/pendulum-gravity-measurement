# 程序3：实时天气（AppId::WEATHER）

## 概述

通过和风天气 QWeather API 获取实时天气数据，在 OLED 上以四屏循环显示。支持自动重连、紧凑缓存、断网降级。

## 数据源

| 项目 | 值 |
|---|---|
| 平台 | 和风天气 QWeather **免费订阅**（v7）|
| 接口 | `/v7/weather/now`（实况）+ `/v7/weather/24h`（24 小时预报）|
| 认证 | Key + Host（NVS 存储源码不写死）|
| 坐标格式 | **经度,纬度**（注意顺序！）|
| 响应编码 | identity 明文（本工具链无 zlib，**不可**请求 gzip —— 见下「zlib 缺失」）|
| 更新周期 | 30 分钟（`WX_PERIOD_MS`）|

## 默认位置

- 张家口市第一中学：经度 114.88°E，纬度 40.77°N
- 可通过 BLE [4] → [4.2] 修改坐标

## OLED 四屏（短按切换）

| 屏幕 | 内容 |
|---|---|
| ① 气温 | 当前气温大字显示 + 体感温度 + 湿度（气压字段和风 API 返回但本屏未占用，留待后续版本）|
| ② 天气 | 天气现象中文名 + 点阵图标（晴/云/雨/雪/雾）+ 今日最高/最低温 |
| ③ 风速 | 风速风向 + 风力等级 |
| ④ 降水 | 未来 6 小时降水概率竖条点阵（pop≥30% 显示）+ 开始时间 |

每屏角标显示 `HH:MM 数据年龄`；超过 24h 追加 `!` 标记。

## 缓存策略

### 紧凑格式（24h 预报）

原始 JSON ~5-6KB → 超过 NVS 单值 ~4KB 限制 → 压缩为：

```
fxTime(16字符)|temp|pop;fxTime|temp|pop;...
```

约 600B，可安全存入 NVS。解析函数 `compactHourly()` / 按页读取时按 `\|` 和 `;` 分割。

### 降级原则

1. 有网有缓存 → 后台静默更新
2. 有网无缓存 → 首次拉取，屏显等待页
3. 无网有缓存 → 显示缓存数据 + 角标年龄
4. 无网无缓存 → 显示"无数据"

## 自动重连

程序3 需要联网但 WiFi 未连接时：
1. 检查是否有任何可用凭据（NVS 用户凭据或内置默认）
2. 若有且距上次请求 ≥30s → 发起连接
3. 连接成功后下一 tick 自动拉取
4. 失败则 30s 后重试（防振荡）

> 出厂未配网也能连（使用 `fw_config.h` 内置的 3 条默认 WiFi）

## 凭据内置说明（2026-10-02）

原先 Key 一律走 NVS、出厂留空，必须先经 BLE `[4.4]` 配一次才能拉天气。
现按用户要求改为**写入固件**（`fw_config.h` 的 `WX_HOST_DEFAULT` / `WX_KEY_DEFAULT`）：

- 出厂即通电可拉天气，无需先配 Key
- NVS 优先级高于内置值 → 换账号用 `[4.4]` 覆盖即可，不必重刷固件
- `app3_weather.cpp` 另有兜底：NVS 被清空时回落到内置值
- ⚠️ 与 WIFI_DEF_* 同为个人私有凭据，**开源前务必清空 `fw_config.h`**

## 异步拉取改造（2026-10-02）

### 故障现象

用户实测报告：**长按按键切换程序完全无效；单摆程序按键正常，但天气程序短按不换屏**。

### 根因

按键状态机的唯一采样点是主循环里的 `Manager::tick() → handleButton()`。
原 `doUpdate()` 在 `onTick` 中调用**同步阻塞**的 `Net::httpGet()`，
一次完整拉取（等 WiFi 连接 15s + DNS 预检 + GET 10s + 分块读流 + GZIP 解压）会独占 CPU
**15–25 秒**。主循环停摆期间按键完全读不到；失败后 30s 重试，往复阻塞。

这同时解释了两个现象：天气程序内短按无效（主循环在阻塞），
以及长按切程序无效（长按需持续采样 1.2s，遇阻塞必然漏采）。

叠加缺陷：`loop()` 原为 100ms 节拍，按键采样率仅 10Hz，短按与长按时长判定误差大。

### 改造内容

| 层 | 改动 |
|---|---|
| `fw_net` | 新增独立 FreeRTOS 任务 `httpTask`（6KB 栈）：承载 DNS 预检 + GET + 读流 + GZIP 解压全部阻塞操作 |
| `fw_net` | 新增 `httpStart()` / `httpPoll()` / `httpBusy()`：主循环只投递请求与取结果，**永不阻塞**；跨线程数据经互斥量 + 二值信号量保护 |
| `app3_weather` | `doUpdate()` 删除，拆为非阻塞状态机 `advanceFx()`：`FX_WAIT_NET → FX_NOW → FX_24H`，每 tick 只推进一小步 |
| `app3_weather` | 新增 `onHide()`：切走程序即终止本轮拉取，保证非活跃程序零网络请求 |
| `fw_config` | `BTN_LONG_MS` 1200 → **800**；新增 `LOOP_INTERVAL_MS` 10ms 与 `TICK_INTERVAL_MS` 100ms 两级节拍 |
| `fw_manager` | 按键采样提到 100Hz（独立节拍），`onTick` 业务分发仍节流 10Hz（≤10Hz 契约不变） |
| `fw_manager` | 新增 `[Btn]` 串口诊断日志（按下/短按/长按触发），便于上板验证 |

### 关键约束（后续修改必读）

1. **`onTick` 内禁止任何阻塞调用**（HTTP、DNS、`delay` > 50ms）。按键采样与业务分发共用主循环。
2. 网络任务内**禁止 `EventBus::broadcast`** —— 会碰 NVS/`String`，与主循环竞态。
3. 同时只允许一个在飞 HTTP 请求；`httpStart()` 忙时返回 `false`，调用方下 tick 重试。
4. `advanceFx()` 失败时必须复位 `_fx = FX_WAIT_NET`，否则重试会卡在已失败阶段（异步化后 `_fx` 记录进度）。
